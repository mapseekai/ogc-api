# 全局代码规范

通用规则适用于所有语言；语言与框架规则按涉及的代码选用，项目及组件规范补充具体要求。

## 命名与一致性

- 沿用适用的规范和同类实现，不另创一套写法，也不复制已确认的缺陷。
- 同一概念使用一致术语；名称表达真实职责，避免自造缩写和无意义后缀。

## 文件组织

- 按职责划分文件，文件名反映主要内容；相关代码就近放置。
- 不按行数机械拆分，不强制每个类型或函数独占文件。

## 文件布局（自上而下阅读）

先展示主要概念和公开入口，再展开实现细节。以下顺序以不改变语言语义、初始化顺序和工具约束为前提。

### 文件内顺序

1. 模块声明与导入。
2. 文件级常量。
3. 主要类型或公开入口。
4. 从属类型与辅助实现。

从属类型放在主要类型之后；与类型分离的实现块放在对应类型定义之后。同一 API 的类型按请求、成功响应、错误排列。

### 方法与函数顺序

- 构造或工厂方法 → 公开方法 → 私有辅助方法。
- 同一职责内，调用者优先放在被调用者之前，便于顺着调用链向下阅读。
- 承担主体逻辑的辅助函数在前，格式化、简单查找等末端辅助函数在后。

### 测试顺序

- 导入 → 测试常量 → 测试用例 → 辅助函数。
- 相关测试按场景分组，共享辅助函数放在共同作用域；避免无意义的分组和深层嵌套。

## 简洁与复用

- 优先复用标准库、已有依赖和项目能力，新增实现前先查找。
- 只合并语义一致、需要共同维护的逻辑，不因代码相似强行抽象。
- 不为假设的未来需求增加抽象、配置、兼容层或依赖。
- 使用直接的控制流，避免无意义包装和过深嵌套。

## 接口与资源

- 遵守项目依赖方向，通过约定的公开接口调用，不穿透模块内部实现。
- 明确表达依赖和副作用，不用隐式全局状态传递业务数据。
- 明确资源和任务的归属，处理正常、失败和取消路径的清理；避免资源使用随不受控输入无界增长。

## 校验与错误

- 在信任边界校验输入；内部约束已可靠建立且持续有效时，不重复检查。
- 用正确的类型和接口表达缺失与失败，不用默认值或强制转换掩盖问题。
- 在能处理的位置处理错误，否则保留原因向上传递；不吞错、不逐层重复记录。
- 兜底、重试和回退应有明确场景；不得以简化为由删除必要的权限、隔离和资源保护。

## 注释与验证

- 注释解释原因、约束和必要的算法步骤，不复述代码；变更同步更新相关文档。
- 重构保持已有契约，不顺带修改无关功能；修复缺陷补充回归测试。
- 使用项目工具格式化并运行相关检查与测试；不以跳过检查或削弱断言换取通过。

## Go

- 使用 `gofmt` 格式化；导入按标准库、第三方、项目内包分组。
- 包名使用简短小写单词；文件名使用 `snake_case.go`，测试文件使用 `_test.go` 后缀。
- 导出名称用 `PascalCase`，未导出名称用 `camelCase`；缩写保持 `ID`、`URL`、`HTTP`，如 `userID`。
- 同一类型的接收者名保持一致；修改状态或包含锁的类型使用指针接收者，避免复制锁。
- 接口按调用方需要定义，保持小而明确；不为每个结构体配一个接口。
- `error` 放在返回值最后，错误分支尽早返回；不使用 `panic` 处理正常业务失败。
- 用 `errors.Is` / `errors.As` 判断错误，不匹配错误字符串；需要保留可检查原因时用 `%w` 包装。
- 需要上下文的函数将 `ctx context.Context` 放在首个参数，并向下传递，不用 `context.Background()` 截断请求链。
- 成功获取需释放的资源后尽早安排 `defer`；循环内不要把每轮资源的释放拖到整个函数结束。
- 普通函数默认同步完成；启动 goroutine 时明确退出条件和结果、错误的接收方。
- 同类多场景测试使用表驱动和 `t.Run`；测试辅助函数调用 `t.Helper()`。

## 本项目测试文件约定

- 每个源文件的测试统一放在同目录的同名测试文件中，例如 `engine.go` 对应 `engine_test.go`。
- 单元、回归、压力、模糊测试及基准测试按被测职责合并，不以 `audit`、`review`、`regression`、`stress` 等来源或阶段另建测试文件。
- 测试覆盖多个源文件时，按主要被测入口归属；只测试另一模块的逻辑时，移入该模块对应测试文件。
- 共享夹具放在最相关测试文件的辅助区，通过包内作用域复用。
- 核心包测试优先通过公开接口验证；示例和开发工具可使用同包测试。两种方式均保持同名文件约定。
- `make fmt` 固定三组导入；`go run scripts/check_go.go` 检查文件配对、声明顺序、辅助函数标记、接收者一致性和公共 GoDoc。
